# Feature Specification: 純文字點餐軟體

**Feature Branch**: `001-text-ordering-app`

**Created**: 2026-10-20

**Status**: Ready for planning

**Input**: User description: "Python 寫一個純文字介面的點餐軟體"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 瀏覽菜單並建立訂單 (Priority: P1)

顧客啟動軟體後可以瀏覽餐點與價格，選擇餐點及數量，建立一份訂單並查看目前內容。

**Why this priority**: 建立訂單是點餐軟體的核心價值，也是其他功能的前置流程。

**Independent Test**: 從主選單查看菜單、加入至少兩項餐點、修改數量並查看小計，
即可確認顧客能完成基本點餐流程。

**Acceptance Scenarios**:

1. **Given** 顧客啟動軟體，**When** 顧客選擇查看菜單，**Then** 系統顯示每項餐點的編號、名稱與價格。
2. **Given** 訂單為空，**When** 顧客輸入有效餐點編號與數量，**Then** 系統將餐點加入訂單並顯示更新後的小計。
3. **Given** 餐點已在訂單中，**When** 顧客再次加入該餐點，**Then** 系統累加數量而非建立重複項目。

### User Story 2 - 檢視與修改購物車 (Priority: P2)

顧客可以檢視目前訂單、修改餐點數量或移除餐點，確保送出前內容正確。

**Why this priority**: 修改能力可避免輸入錯誤導致錯誤訂單，直接支援可靠的結帳流程。

**Independent Test**: 先建立含有餐點的訂單，再增加或減少數量、移除一項餐點並重新查看總額。

**Acceptance Scenarios**:

1. **Given** 訂單含有餐點，**When** 顧客選擇檢視訂單，**Then** 系統顯示各項名稱、單價、數量、項目小計與訂單總額。
2. **Given** 訂單含有餐點，**When** 顧客將數量改為正整數，**Then** 系統以新數量重新計算小計與總額。
3. **Given** 訂單含有一項餐點，**When** 顧客將該項數量設為零或選擇移除，**Then** 系統移除該項並正確顯示空訂單狀態。

### User Story 3 - 確認訂單並取得摘要 (Priority: P3)

顧客確認內容無誤後可以送出訂單，取得包含訂單編號、明細與總金額的文字摘要。

**Why this priority**: 訂單摘要是點餐流程的完成點，讓顧客知道系統已接收哪些內容。

**Independent Test**: 建立含有至少一項餐點的訂單並確認，驗證摘要包含訂單編號、明細與總額。

**Acceptance Scenarios**:

1. **Given** 訂單至少含有一項餐點，**When** 顧客選擇確認訂單，**Then** 系統顯示訂單編號、餐點明細與總金額並清空目前購物車。
2. **Given** 訂單為空，**When** 顧客選擇確認訂單，**Then** 系統拒絕送出並提示先加入餐點。

### Edge Cases

- 顧客輸入不存在的選單選項、餐點編號或非正整數數量時，系統提示錯誤並保留目前訂單。
- 顧客在空訂單上檢視、修改或確認時，系統顯示明確的空訂單提示，不應崩潰。
- 顧客輸入空白、負數、小數或超出可處理範圍的數量時，系統拒絕該輸入。
- 顧客選擇離開時，系統在有未確認訂單的情況下要求明確確認，避免意外遺失。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 以純文字主選單提供查看菜單、加入餐點、檢視訂單、修改訂單、確認訂單與離開功能。
- **FR-002**: 系統 MUST 顯示預先定義的餐點編號、名稱與非負價格。
- **FR-003**: 系統 MUST 驗證餐點編號存在且數量為正整數後，才將餐點加入訂單。
- **FR-004**: 系統 MUST 以餐點編號合併相同餐點，並正確計算項目小計與訂單總額。
- **FR-005**: 系統 MUST 允許顧客查看、更新數量與移除訂單項目。
- **FR-006**: 系統 MUST 對無效輸入顯示可理解的錯誤訊息，且不得遺失目前有效訂單。
- **FR-007**: 系統 MUST 阻止空訂單確認，並在有效確認後顯示訂單編號、明細與總額。
- **FR-008**: 系統 MUST 將點餐流程封裝為可測試的程式元件，將終端機輸入輸出與訂單計算邏輯分離。
- **FR-009**: 系統 MUST 在程式例外或輸入錯誤時顯示診斷資訊，不得以成功結果掩蓋失敗。

### Key Entities

- **MenuItem**: 可供點選的餐點，包含唯一編號、名稱與價格。
- **OrderItem**: 訂單中的餐點項目，包含餐點、數量與計算所得的小計。
- **Order**: 顧客目前建立或已確認的訂單，包含項目、總額與狀態。
- **OrderReceipt**: 確認訂單後提供給顧客的摘要，包含訂單編號、明細與總額。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新使用者可在 60 秒內完成查看菜單、加入一項餐點並查看總額。
- **SC-002**: 100% 的有效測試案例能正確計算餐點小計與訂單總額。
- **SC-003**: 100% 的無效輸入測試案例會獲得錯誤提示，且不會讓程式意外終止。
- **SC-004**: 顧客可在確認前完成檢視、修改與移除餐點，並在確認後取得完整文字摘要。

## Assumptions

- 使用者能閱讀終端機中的繁體中文文字並透過鍵盤輸入。
- v1 使用固定的記憶體菜單，不包含資料庫、登入、付款、庫存或外送整合。
- 金額以整數元計算，不處理折扣、稅額或小數貨幣。
- 訂單只在目前程式執行期間存在；確認後產生本次執行中的唯一訂單編號。
